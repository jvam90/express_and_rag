O que é RAG:

Basicamente, fornecer contextos "privados" para uma LLM. Meus dados, meu contexto para a LLM. Uma LLM é treinada até certo ponto. Depois disso,
ela pode não conhecer, por exemplo, o contexto de uma empresa, de um projeto, etc.

Casos de uso:

-assistentes
-FAQ dinâmico
-contextos privados de uma instituição

1)Preparação: os documentos são divididos em pedaços (chunks). Uma LLM vai ser usada para transformar os chunks em uma sequencia de números,
processo conhecido como embedding. Basicamente é uma representação vetorial daquele conteúdo, que vai ser guardado em um banco de dados apropriado
(banco de dados vetorial).

2)Busca/geração: 

-a pergunta feita pelo usuário é convertida também em números (embedding).
-o sistem compara o embedding da pergunta com o que existe no banco de dados vetorial, encontrando o que é mais parecido.
-o sistema retorna os documentos e a pergunta feita.
-a IA monta a resposta com base nesse contexto retornado.

Vantagens

-a IA para de adivinhar e vai buscar respostas em uma fonte de verdade
-aumenta a transparência, pois eu defino qual será a fonte de verdade
-permite acesso a dados mais recentes, uma vez que são mais controláveis


Ferramentas que serão usadas:

1)LangChain é um framework de código aberto que facilita o desenvolvimento de aplicações utilizando Grandes Modelos de Linguagem (LLMs), 
como o GPT da OpenAI. Ele atua como uma "cola" ou orquestrador, permitindo integrar inteligência artificial a fontes de dados externas 
e ferramentas de software.

2)Qdrant: banco de dados vetorial

3)OpenAI: plataforma de LLMs para acesso por meio de uma conta

*Se for usar o qdrant, ele possui uma página de dashboard: http://localhost:6333/dashboard

Configurando o qdrant

Qdrant é o banco de dados vetorial que será utilizado no projeto. Como ele se trata de uma API, é preciso de uma URL na sua instanciação:

export const qdrantClient = new QdrantClient({
  url: config.qdrant.url, //url no arquivo de config
});

O próximo passo é criar a collection que guardará os dados:

//Criar uma coleção no qdrant ao inicializar a API, se ela não existir
export async function initQdrantCollection() {
  const collections = await qdrantClient.getCollections();
  const collectionName = config.qdrant.collection;
  const exists = collections.collections.find((col) => {
    col.name === collectionName;
  });

  if (!exists) {
    await qdrantClient.createCollection(collectionName, {
      vectors: {
        size: 1536,
        distance: "Cosine",
      },
    });

    console.log(`${collectionName} criada no qdrant`);
  } else {
    console.log(`${collectionName} já existente no qdrant`);
  }
}

Primeiro se busca pela collection. Se não existir, ela deve ser criada, passando seu nome e alguns parâmetros:

vectors: objeto que tem o tamanho e a distância. Tamanho é o tamanho de cada vetor e distância é a forma que o algoritmo vai buscar pelas diferenças.

Configurando o OpenAI

Configurar o OpenAI neste contexto, é definir como vão ser processados os chunks e como vão ser processadas as consultas feitas pelo usuário:

import { ChatOpenAI, OpenAIEmbeddings } from "@langchain/openai";
import { config } from "../config.js";

const openApikey = config.openai.apikey;

//Vetorização dos textos
export const embeddings = new OpenAIEmbeddings({
  openAIApiKey: openApikey,
  model: "text-embedding-3-small",
  maxRetries: 2,
  timeout: 10000,
});

//Processamento das mensagens (prompts)
export const llm = new ChatOpenAI({
  apiKey: openApikey,
  model: "gpt-4o-mini",
  temperature: 0,
  maxRetries: 2,
  timeout: 20000,
});

A configuração é semelhante: é preciso da chave da openai pra uso de suas apis, modelo a ser usado para cada tarefa, número máximo de tentativas e timeout.
No processamento das mensagens, uma propriedade a mais é configurada: temperature. Em termos simples, ela indica o quanto o modelo deve "imaginar" na hora de inferir algo.
No contexto de RAG, sempre que possível, usar temperature igual a zero, pra evitar alucinações.
